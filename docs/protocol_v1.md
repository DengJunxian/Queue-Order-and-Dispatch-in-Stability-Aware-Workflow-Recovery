# SAIL 研究协议 v1.0

日期：2026-10-25。状态：**研究设计定稿，正式实验尚未冻结或运行**。本协议实现用户已批准计划中的 P0；P1/P2 负责实现与正确性验证，P3 按本协议选择参数，G2 再封存代码、配置和场景。现阶段没有 SAIL 性能结果。

## 1. 科学问题与主张

多个独立 DAG 共享异构计算节点时，单个节点故障会迫使任务迁移，也可能延迟逻辑上不依赖故障任务的其他任务。研究问题是：**在线预计的保护任务延迟，能否帮助选择有限修复范围，在预定恢复性能预算内减少这些任务的延迟？**

“协作”指工作流在同一资源池中的恢复协调，不假设工作流间存在数据依赖。有限范围、依赖感知恢复和多目标加权均有先例。候选增量是固定保护集合、可在线计算的延迟项与范围选择之间的可验证关系。

主假设 H1：SAIL 相对 B2 降低 CDI，AWCT 平均相对增幅的单侧 95% 上界不超过 5%。机制假设 H2：SAIL 相对 NoStability 的 CDI 改善支持显式稳定性项的作用。H3：与固定 H0/H1/H2 比较，检验适应不同场景的价值；若固定范围同样有效，保留此结果并收窄自适应主张。5% 是预先规定的研究容忍度，不是业务 SLA。

## 2. 数据与划分

原始来源固定为 WfInstances commit `249866063b3bd7d6a36a5a55d4202c1f683099c0`；schema/官方 validator 固定为 WfFormat commit `017160621265bc22d8d6f1cd6f8c875e287fc292`。逐文件路径、Git blob、SHA-256、拓扑组和用途以 `data/manifest_v1.json` 为准。

20 份真实执行记录含 1,283 个任务、1,965 条边、2,493 个文件。仅 7 组不同的家族内无标号有向拓扑：Montage 58/103、Epigenomics 41/73、SRA Search 42/64/84。SRA 每规模的五次日志是同拓扑重复执行。真实日志只提供结构、工作量和文件量，不提供本研究的故障轨迹或性能结论。

- 核心测试：19 份 40–90 任务记录，6 个拓扑组；全部禁止用于参数搜索。
- 规模留出：Montage 103 任务记录，1 个拓扑组；只用于预先登记的扩展，不计入核心预算，也不替换主测试。
- 开发和验证：独立合成 DAG；不以这 20 份记录训练 WfChef、拟合参数或选择有利场景。知道测试拓扑用于数据核查不等于获得新的测试样本。
- 合成生成器采用三种模板 L=链、R=层状图、F=fork-join。A=L+R+F，B=2L+R，C=R+2F，这些是独立的合成任务类型，不冒称真实应用生成模型。每个三工作流槽位 q 的节点数为 `{48,64,80}[(i+q) mod 3]`，i 为该数据划分内的根种子索引。链为相邻任务连边；层状图按任务ID轮流均匀分入8层，相邻层每对节点以0.25概率连边，随后按task ID扫描，为没有前驱/后继的非首/末层节点均匀随机补一条相邻层边；fork-join 为单源、其余中间节点、单汇。每任务工作量独立 lognormal(0,0.8)，每边数据量独立 lognormal(0,1)，随后按与真实数据相同的尺度规则归一化。参数是设计值，不是对真实测试记录的拟合。
- 开发根种子 `10000..10019`；验证根种子 `20000..20009`；正式测试根种子 `60000..60029`，资源不足版本只用事先登记的 `60000..60009`。合成数据 i 分别为 seed−10000、seed−20000；不同工作流槽位使用独立的稳定ID随机流。

原始时间戳存在 37 处非规范格式，保留原文并只作来源元数据；仿真不使用 `createdAt`/`executedAt`。不修补运行时间、不删除长任务。原始文件未修改；解析结果单列。

## 3. 场景与随机性

三个工作流均于仿真时间 0 到达，各有独立任务 ID 命名空间。Mix A=1M+1E+1S，B=2M+1E，C=1E+2S。M/E/S 为 Montage/Epigenomics/SRA Search；工作流完成时刻是各自所有任务完成时刻的最大值。

测试实例按根种子索引 `i=seed-60000` 确定，不按结果选择。核心 M 池按文件名排序，槽位 q 取 `(i+q) mod 2`；E 同规则；S 先按任务数 `{42,64,84}` 取 `(i+q) mod 3`，再取该组按文件名排序的第 `(floor(i/3)+q) mod 5` 份日志。q 是该家族在 Mix 中的零起始出现次序。每份重复工作流有不同实例 ID，但不增加独立样本量。

单节点同时执行一个 CPU 任务。节点数 `m∈{4,8}`。生成 8 个 `U(0.5,1.5)` 速度，取前 m 个并将均值归一为 1。任务 v 的预计工作量是其原始 `runtimeInSeconds` 除以所属工作流平均原始任务运行时间；预计执行时间 `p_hat(v,j)=work(v)/speed(j)`。主实验比较标准化后的工作流形状与恢复行为，不解释为原测量集群上的秒级预测。原始尺度结果仅作另行冻结的扩展。

随机流使用 NumPy PCG64，种子由 UTF-8 字符串 `protocol_v1|root_seed|mix|stream|stable_id` 的 SHA-256 前 16 字节按 little-endian 转成整数。stream 分为 platform/failure/runtime/synthetic；不包含 method，不依赖方法调用次数。共享工作流槽位的 runtime 随机量跨节点数、CCR、故障时机复用，node speed 跨这些轴复用；每个已实例化场景必须序列化保存实际向量。

故障节点由 failure 流均匀抽取 `[0,m)`，包括对当前任务无影响的节点，不因 F 或 P 为空重抽。故障时刻是对应实际无故障参考 makespan `M0` 的 0.3 或 0.6。`M0` 和故障未来事件仅对实验管理器可见。无影响故障仍保留在无条件主结果；`F≠∅` 的共同故障前快照定义有效故障分层。

## 4. 故障与任务状态

仅一次永久节点故障，即刻检测；不复制任务、不设 checkpoint。完成输出在完成事件时持久化，持久化写入开销在主模型中为零。已完成任务不重跑；健康节点运行中任务不被抢占；故障节点运行任务的未提交计算丢失，从头执行。

事件顺序以 `(time,event_priority,stable_id)` 排序。同一时刻依次处理：CPU 完成及输出提交、输入准备完成、节点故障、已到期的调度应用、输入准备启动与 CPU 派发。若完成与故障同刻，完成先提交。CPU 完成事件带 attempt ID，旧 attempt 的迟到事件必须被忽略。相同时间的派发按 node ID、任务 ID 排序。

故障处理后、所有方法共有的快照定义：D=已完成；R=健康运行中；I=被中断而回到待执行的任务；Q=所有待执行任务，含 I、排队及输入准备中的任务；F=Q 中原分配给故障节点的任务。所有 F 均必须迁移。`Desc(F)` 是原始工作流逻辑 DAG 上 F 的严格后代闭包，不含资源队列边。

保护集合 `P={v∈Q\F : v 原分配在健康节点，且 v∉Desc(F)}`。P 在共同快照上算一次，对全部方法固定；不根据方法输出、未来是否延误或是否重新分配改成员。`|P|=0` 的 CDI 为 NA，同时报告比例；候选评分中稳定性项设为 0 并标记不适用。

## 5. 通信与执行队列

保留实际 DAG 文件依赖。边数据量为生产者 outputFiles 与消费者 inputFiles 交集的字节数之和；外部输入视为已部署到各健康节点，不计入内部 DAG 通信。本批数据所有生产消费关系均由直接依赖表示，无需补边。

CCR 是参考速度 1 上平均逻辑边传输时间除以平均标准化任务工作量。设 `pbar=mean_v work(v)`，`dbar=mean_(u,v) d_uv`，每场景统一有效带宽 `B=dbar/(CCR*pbar)`，CCR 为 0.5/2。B 在故障前计算并固定，所有方法共用，不按实际同节点传输比例重新调整。

为使“无输入预取”可执行，本版本采用以下统一规则：任务全部逻辑父任务完成后，才开始准备输入；不在依赖尚未齐备时提前传输。输入准备与其他任务的 CPU 执行可并行。同一任务的远端文件按固定 file ID 顺序通过该任务的有效带宽 B 串行读取，因此准备时长为所有远端必需文件总字节数/B；不同任务的传输互不争带宽，主模型不支持拥塞控制主张。

健康生产节点与消费节点相同时读取为零。生产节点故障后，从持久化存储按 B 读取；不能使用故障节点缓存。已完整准备到健康消费节点的输入不因生产节点后来失效而消失。输入准备按消费者任务独立记账，不跨消费者共享缓存。

若任务换节点，取消其旧输入准备并在新节点从头准备远端输入；已发生的传输字节仍计入开销。未换节点的准备与数据继续有效；若源生产节点在读取途中故障，剩余数据由持久化副本以同样B继续读取，主模型不加切换开销。被中断任务在新 attempt 重新准备输入。部分传输按经过时间×B 计入实际字节，达到文件大小为止。

执行时按候选计划给出的每节点固定队列：CPU 空闲且队首的逻辑依赖、输入均就绪才启动，不越过队首回填。H 外任务之间的相对顺序不得改变。生成计划必须保证逻辑依赖加资源队列边仍为 DAG，避免队首互相等待。预计时间只用于计划和评分，实际开始时间由事件决定。

## 6. 公共排程内核

全部方法使用同一 HEFT 派生的列表与插入内核；输入准备采用上一节模型，因此论文须说明通信适配，不能声称逐字复现原始 HEFT。

故障前对三个 DAG 的不相连并集生成共同初始计划。rank 为预计平均计算时间加最长后继通信/rank 路径；通信 rank 使用远端边字节/B，所有并列按工作流实例 ID、任务 ID 排序。

候选范围 H 必须含 F。固定 D 和 R；从原队列去掉 H，再为每个健康节点剩余 Q\H 的相邻任务加入零通信的顺序约束边。H 外分配固定，开始时刻可变。对增强 DAG 中前驱已规划的任务，取 rank 最高者；H 内任务考察全部健康节点，H 外只考察原节点。对每节点寻找满足依赖、输入准备和已规划区间的最早可行插入位置，选择预计结束最早者。其余并列依次选较早开始、较小节点 ID、较早插入位置。新任务不得打断 R。

输入准备预测始于所有逻辑父任务预计完成时刻与当前时刻的较大者，再加远端输入总量/B；保留输入准备中的已观测进度。资源顺序约束只约束 CPU 开始，不重复收费通信。将最终节点队列用同一预测事件执行器回放，核验可行性并产生候选指标。

健康 R 的剩余时间估计为 `max(1e-9*pbar,p_hat(v,j)-已运行时长)`，不得读取真实结束事件；主实验预计=实际，误差实验检验此估计局限。复杂度报告依据实现和 profiling；本协议不预先承诺 O(n²m) 或实时性。

## 7. 方法、候选与评分

| 方法 | 可调整集合 | 决策 |
| --- | --- | --- |
| B0 Requeue-EFT / Fixed-H0 | F | 最小强制恢复范围 |
| B1 Dependency-Repair | F∪(Desc(F)∩Q) | 全后代范围；自定义对照，不冒称 DaTR 复现 |
| B2 Global-Dynamic-HEFT | Q | 全待执行范围；不能作为最优解 |
| Fixed-H1 | F 加一跳待执行后代 | 固定局部范围 |
| Fixed-H2 | F 加至多两跳待执行后代 | 固定局部范围 |
| SAIL | H0/H1/H2 | 下式评分选择 |
| NoStability | 同 SAIL | 使用 SAIL 冻结 μ，λ=0 |
| NoChurn | 同 SAIL | 使用 SAIL 冻结 λ，μ=0 |

同一个任务可以同时属于 F 和某后代集合，集合去重。两跳范围沿逻辑依赖最短距离计算，最后与 Q 相交；不能将已完成/健康运行任务加入候选。相同 H 只生成一次；同分配和同节点队列的候选继续去重，保存对应 H 别名。

`J = AWCT_hat/AWCT_ref_hat + λ*CDI_hat + μ*Churn`。`AWCT_ref_hat` 和各任务 `S_ref_hat` 来自故障前、仅用预计量完成的共同无故障计划回放，一经生成固定。`CDI_hat=mean_(v∈P) max(0,S_hat(v)-S_ref_hat(v))/pbar`。

`Churn=|{v∈Q\F:a_new(v)≠a_old(v)}|/max(1,|Q|)`。强制迁移 F 不计惩罚；重新排队本身不计节点迁移，但通过 CDI 和附加队列位移诊断反映。所有方法的 Reassignment Ratio 使用同一定义。

评分绝对差 ≤1e-12 视为并列，依次优先较低 Churn、较小 |H|、较低 hop 编号、分配与队列的字典序。候选无效则记录原因，不静默跳过；任何候选无效首先视为实现问题并阻断 G1/G2。F 为空仍按规则构造范围和 B2，保留无故障影响场景，记录不必要的重新规划。

## 8. 参数选择

λ 网格 `{0,0.1,0.3,1,3}`，μ 网格 `{0,0.01,0.1}`。开发集按同一节点数、CCR、故障比例展开；所有候选一次生成，15 组评分可复用，保存复用范围。筛选开发集平均 `(AWCT_SAIL/AWCT_B2)-1≤0.05` 的参数，按 CDI、AWCT、Churn、λ、μ 递增保留前三组。验证集只比较这个短名单；同样先满足 AWCT 预算，再按该顺序选一组。

若没有参数满足预算，G2 不通过，保留开发记录并修订研究版本；不去测试集寻找新参数。若 λ=0 胜出，照实冻结，不能宣称稳定性项得到支持。若候选全集在大多数开发场景退化为一个计划，记录覆盖率并判断研究是否值得进入正式测试。开发诊断可改变下一协议版本，但版本变更须发生在正式测试前。

目前 `selected_lambda=null`、`selected_mu=null`，表示选择尚未运行；不是协议遗漏。权重决定程序已定稿。

## 9. 评价与统计

实际无故障参考使用相同初始计划、工作量随机场、速度和通信条件，并完整运行；只由离线评估器保存。实际 `CDI=mean_(v∈P) max(0,S_method(v)-S_no_fault(v))/pbar`。它包含容量损失和策略改变两部分，不作因果分解。另报告共同故障条件下相对 B0 的有符号保护延迟 `mean_P(S_method-S_B0)/pbar`，辅助区分恢复策略间的影响。

AWCT 为三个工作流完成时间的平均；makespan、各家族 slowdown、Churn、受保护任务覆盖率、故障有效率、调度 wall time、尝试次数、丢弃计算量和通信字节为附加指标。CDI 汇总先按场景算均值、再在有定义场景等权，不以任务数加权。每次同时报告 CDI 分母场景数和 P 空集数。P95 延迟可描述，但不事后升为主指标。

正式主比较：SAIL−B2 的 CDI 配对差（负为改善）及 AWCT 相对差。机制比较 SAIL−NoStability、SAIL−NoChurn、SAIL−固定 H0/H1/H2 均保留。相同根种子在所有 Mix、节点、CCR、故障时刻及方法下作为一个整体 cluster，按 root_seed 有放回重采样 5,000 次；每个被抽中 block 内保留全部配对关系。先对每个 Mix/轴组合等权平均，再对 Mix 等权。不能按 Mix 独立抽取同一个根种子，不能把任务、方法数或日志重复数当独立 n。

报告双侧 percentile 95% CI；预定 AWCT 预算用同一 bootstrap 分布的单侧 95% 上界。固定基准集的区间只覆盖模拟环境随机性，不外推全部科学工作流总体。机制探索仅作效应量和区间描述；若添加显著性 p 值，必须对上述五个机制比较以 Holm 校正并保留未校正值，不能结果出来后只挑显著对照。

继续投稿的预设支持条件：整体 CDI 配对区间上界<0，至少两个 Mix 的点估计方向一致，AWCT 相对差单侧上界≤5%，并且消融/固定范围结果足以解释具体机制。未满足时仍完整报告原假设结果，再评价是否有更窄发现；不能将新发现冒称原确认性假设。

## 10. 主预算与稳健性

主轴为 3 Mix×2节点数×2 CCR×2故障时机×30根种子=720故障场景。8个唯一方法计5,760次故障运行，加360次无故障参考，共6,120次核心运行。若在正式测试前因开发 profiling 冻结10根种子版本，则240场景、2,040次核心运行。

两项必做稳健性均使用 Mix×CCR×前10正式种子，节点4、故障0.6M0，共60场景：

1. 实际工作量=预计量×`exp(σZ−σ²/2)`，`σ=sqrt(log(1+CV²))`，CV=0.1/0.3。任务的 Z 跨方法/条件复用，重试使用同一完整工作量，不按方法抽新噪声。每误差水平4主方法，共480次，另120次匹配无故障参考。实际工作量、未发生的完成事件对调度器不可见。
2. 公共控制延迟 δ=0.1 pbar，共240次；δ=0结果复用主实验。故障后暂停所有新 CPU 派发，运行中任务与已开始的输入准备继续；在 τ+δ 的新快照上应用原 H 边界并重算可执行计划，保持原 F/P/Q 评价集合。因暂停派发，不会出现 Q 中任务在规划期间已经开始；完成和已准备输入必须保留。该实验是统一等待成本的敏感性分析，不等同各算法真实 wall time 注入。

合计推荐6,960次，10种子版本2,880次。这是8个方法配置标签的名义预算；若冻结λ/μ使消融配置完全等价，记录alias与复用次数，不能把等价结果当独立证据。开发、验证、实现测试、调度耗时重复和103任务规模留出不含在内。P3用20个覆盖最大节点数/高CCR/不同合成模板的开发场景计时，含原始日志与分析余量估计；若30种子版本预计≤12小时则选30，否则10种子版本≤12小时才选10，两者均超限则重排日程。选择不得使用正式测试效果。
